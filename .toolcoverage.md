1. Subject coverage — which mathematical and physical topics the system understands.
2. Reasoning coverage — which kinds of derivations and proofs it can perform.
3. Visualization coverage — which reusable visual tools and animation patterns it supports.

A strong workflow is:

User question
→ classify domain and difficulty
→ extract knowns and unknowns
→ identify governing principles
→ choose symbolic or numerical tools
→ solve
→ independently verify
→ create teaching sequence
→ select reusable visual tools
→ compile scene
→ validate layout and physics
→ preview render
→ review frames
→ repair only where needed
→ final render

That would make ProofMotion useful not only for mathematics and physics, but for a broader class of technical explanations.
